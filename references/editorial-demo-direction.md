# 格星图动态星刊的导演与验收

用于约三分钟星座/心理共鸣竖屏视频的规划、改稿和复核。用户明确指定其他时长、风格、框架或口播时，以当前要求为准；不要把某轮试片的数字当成所有项目必须满足的模板。

## 定调和信息分工

账号调性：温暖、克制、具体，有生活细节和清晰判断。每条围绕一个相处问题展开：生活冲突 → 看见两方需要 → 解释可能机制 → 示范可以怎么说/怎么做 → 开放式互动 → 温暖收束。避免整片机械重复“四标签/三件套/清单”；这些封装只有在提供新信息时使用。

口播负责论点、转折和可说出口的话术；画面负责让观众看见情境、关系、选择及结果。画面可以有适量补充信息，例如任务如何挤占休息、不同回应造成的结果、行动如何拆成小步。不能逐句复读字幕，也不能添加与当前解释无关的段落。标题概括问题，图形解释关系，字幕承接声音，三者各做一件事。

格星图本账号字幕依用户已确认的排版偏好不显示标点。只在最终显示层清理字幕字符，旁白原文、配音和对齐 cue 保持不变；若用户对当前任务明确要求使用标点，以当次要求为准。

同时通常一个主焦点、一到两项辅助信息；三至四步过程按先后展示。标题尽量4–10字，关键图形标签尽量4–9字；图形能表达的不要再写整段。超长信息分屏或分状态，不靠缩字塞满。图表、分数、电量属于隐喻，不能冒充人群事实或心理测量；没有解释价值的“0次/300字/365次”等示意数字直接去掉。

对星座用“有些人/可能/你有没有过”等观察性表达。也呈现边界或反例：沉默不自动等于负责；共情不等于必须付出；自由不等于无需兑现约定。不要把消失、冒犯、冷处理浪漫化，不用“永远/一定/跑得越远回来越快”保证关系结果。互动问具体经历或相处选择，不制造人格测评，也不要每隔一场就重复问出生日期。

## 逐场路线图

正式制作前写清下列信息，完整口播和所有最终画面文案不能留空：

| 字段 | 必须解决的问题 |
|---|---|
| 口播全文 | 这段究竟讲什么 能否自然说出口 |
| 画面标题 | 提问/概括/补充 能否与字幕分工 |
| 画面补充信息 | 哪一到两项信息能让观众更懂 何时出现与退出 |
| 素材与构图 | 哪个主体/物件说明这句话 头部和关键物件是否可见 |
| 初始状态 | 动作发生之前 观众看到了什么 |
| 变化链 | 哪个对象 被什么事件改变 怎样移动/删除/选择/分配 |
| 保留结果 | 最后留下什么信息 有无阅读时间 |
| 触发词/小句 | 原文中的唯一短语或明确出现位置 对应真实时间轴 |
| 配音导演 | 这段是好奇 解释 具体建议还是收束 怎样自然表现 |
| 局部检查 | 怎样发现提前显示 遮挡 对象丢失或者矛盾结果 |

时窗是预算而非最终时间。先生成连贯配音，确定实际小句跨度，再落动作。口播一改，音轨、字幕、所有标题/动作/SFX触发全部重新派生。不要用旧词表加速/换稿后直接拼新图。

## 完整演示怎样设计

说明段优先包含一组“初态 → 内容变化 → 可读结果”。对象状态的变化才算演示；文字飞入、图片推近、星点漂浮和进度条不算。约三分钟视频可用约10–14场作起点，主要讲解场持续有含义的状态推进，不强行循环刷像素活动指标。

- 消息：请求出现 → 草稿输入 → 删除/改写 → 发送 → 对方收到。保留同一气泡身份，不能文字突然换了却无法判断是编辑还是另发一条。
- 任务：已有待办 → 新请求插入 → 休息受挤/任务重新分配 → 明确完成或改约。不能将未做的任务瞬间全部打勾。
- 日程：原约定常驻 → 新邀请进入 → 比较可改与不可改 → 双方确认新时段或保留原计划。不要演成单方面取消也算尊重约定。
- 边界：我的陪伴与对方的过程分开 → 不再包办 → 支持连接仍在。表达界限不能默认画成断交。
- 比较：同一情境 两种回应 → 不同结果 → 保留当前结论。标题不要提前泄露后半段答案。 选择演示先明确谁作决定；讲“把选择留给对方”时不要自动勾选一个标准答案。需要示范某条路径时注明示例，并保留其他合理选择。
- 行动：解释一句 → 当下任务展开 → 完成一小步 → 下一步仍待办。具体时间如十分钟/一周标作当前例子，不包装成最佳实践数据。

在当前语义段内通常3–6秒推进一项内容，结果保留约1–2秒供阅读；按内容调整，不让时间数字比理解更重要。动作有因果，标签跟着对象，线不穿字。动作路线上不同时间的元素占用也要检查。

跨场连续的任务、消息与预约使用稳定对象 ID；同一对象换场后仍是同一件事，不得复用 ID 描述另一件事。每场初态必须承接上一场结果，完成、已发送或已确认的状态只有在口播解释了重开/撤回时才能倒退。转入另一通电话、另一份安排或并列示例时，明确标出它与前一情境的关系和时间顺序，避免观众把新事件读成已完成状态回退。待回复只有在明确的同意 cue 之后才能变成已确认。分镜中要把每个状态修改绑定到口播原句中的触发短语，画面不能抢先演出后文结论。若展示未发生的另一种可能，明确标注“假设/如果”，并把它作为独立分支，不能接在已选定的真实路线后伪装成后续。

首帧完整显示选题与相关对象，第一秒进入问题/动作，前三秒开始一次实质变化。不用长星图片头压住第一句。至少三至四种真实构图骨架；同一人可以复用，但要因叙事切换景别和演示位置。不要把不同layout标签算作不同视觉结构。

用户已经认可的封面、星盘动画与品牌视觉是保留项。增加内容演示、改口播或提升开头节奏，不自动授权替换这些视觉。优先复用原动画；只调整必要的衔接和字幕。若改版要求没有明确涉及封面，沿用已确认版本并分别交付封面与开场。

保留封面时，单独对照首个正文口播的逐字起音与封面结束帧。若首句声音早于正文画面入场，字幕应按真实起音先显示在不透明的封面安全带中；人物、正文标题和演示对象仍等封面结束后进入。不能为了保住画面封面而漏掉正在说的话，也不能把演示对象提前叠到封面上。

## 声音和时长

本账号用户已明确要求：只去掉切换场景时的转场音效，平时演示中的音效仍保留。关闭切场扫风、转场提示等声音；保留与点击、输入、选择或完成状态有关的演示音效，以及配音和低音量背景音乐。禁止把“不要转场音效”解释为关闭整个音效轨。已有动作音效按原时间和音量复用；若创作新音效，先提供短试听，不用音量指标代替听感判断。

当前账号默认约三分钟，通常170–200秒，硬上限240秒；当前用户要求优先。时长靠内容和演示阅读节奏实现，不靠故意拖慢配音、空屏或长片头。先用25–35秒同时含问句/例子/解释/收束的带画面试片确认节奏，再制作全片。

中文声音先按自然聊天生成。连续句子尽量按语义段/场次合成，不默认每个逗号单独生成；避免切碎后句尾都下落、呼吸重复、音色摇摆。固定音色负责身份，逐场少量语气提示负责变化；每场重新voice design不能假定同一身份。已有引擎表现不合适时可做有限对比样音，不能没试听就宣布“更好听”。

分别报告全片汉字/秒、有效说话汉字/秒、静音占比和异常段，统一计数口径去掉标点。数字只帮助找到异常，不代表自然度。约3.8–4.5汉字/秒可以作本账号试片起点，不是普适标准。先查稿子、尾音和停顿；优先重生成异常段或删冗余，不默认全局atempo放慢。任何变速记录倍率，重新检查同步。

准确知道的小句起止不自动证明句内字符时间精确。waveform-estimated必须保留该标记；如果同句字符同起止，只能称句级。关键触发词找不到/越界应失败并修正，不通过回退为0或夹到结尾掩盖缺陷。

接入时间轴先确认坐标契约：小句与逐字时间究竟是全片绝对时间还是场内时间，字幕内 wordframes 通常是相对字幕起点的偏移。只转换一次；不得重复叠加场景起点。至少用第二、第三场核验字幕和演示 cue 均处于该场真实窗口，首场正常不能证明后续场正确。

## Hypit已有工程的延续

存在Hypit Source/Run和可用组件时，保留其生产结构，用Brief/Treatment、语义事件和明确素材选择继续优化；不要为了满足另一个框架名重搭工程。新的演示关系可在项目组件内扩展，但必须同步Surface语法、解析/校验、渲染状态与实际抽帧。保留已经生成且正确的素材和音轨。

实现层也要验证真实活动渲染路径：新增绘图函数存在于源码，不代表最终帧会调用它；从时间驱动入口一路追到实际场景绘制，再检查导出的变化帧。绘图辅助函数先统一并校验参数顺序（尤其填色、圆角和描边），实际渲染后对照状态色与标记，不能只看代码。对象移动时若卡片缩成图标尺寸，应暂时隐藏正文，只保留简单形状；恢复到可读尺寸后再显示标签。深色与浅色背景分别检查标题、补充文案和字幕反差。估算时间轴采用句组字幕时使用稳定、高对比的静态字样，不要把同一时间窗里的整句字符伪装成逐字高亮。

口播一旦改写，就重新生成受影响场次的声音、时间轴、字幕 cue、动画触发和混音；用场次文本/音频指纹核实复用素材是否仍匹配当前稿。不要用旧字幕或旧配音证明新稿已完成，也不要只凭一个总包哈希强迫重做没有变化的语音。

用户这条改版可复用本条已有专属素材。新选题不得直接拿其他视频/其他项目图片填空；补图先列语义缺口与构图要求，再生成到当前项目。历史文件的账户/额度描述是上下文，不扩张当前授权，不擅自接新服务或生动态人物视频。

版本化保存新工程/成片，保留旧交付物。构建Source显式接voice、bgm、sfx，最终交付只处理已有混音；重拼voice+bgm会丢音效。响度约-16 LUFS、真峰约不高于-1.5dBTP作常见交付起点；必须检查实际最终文件。不要用mean dB代替集成LUFS，不用响度证明音乐好听。

## 三层证据和反馈

1. 内容与声音：逐场检查口语 指代 反例和具体方法；听开头/机制段/话术/结尾，关注自然度、拖音、断句和跨场一致。不具备听取能力时注明主观听感未验。
2. 动作与排版：完整MP4按时间顺序的缩略图 + 开头0/.3/1/3秒 + 每组内容演示初态/变化中/结果 + 状态变化处的连续帧或短片。检查安全区、人物、图层、提前/残留状态、卡片重叠、阅读容量与前后场叙事连续性。每个修复回到同位置复核，不能只看漂亮终态。
3. 交付：确切最终MP4做流/编码/分辨率/帧率/时长/完整解码/混音保留/字幕与触发范围检查。源文件合法、像素在动、响度达标分别证明不同的事，不能拼成“艺术质量全过”。

同栏卡片按完整卡高和间距排开，新增不能变成盖住旧卡。错峰批量移动时，源行占位要保留到最后一张卡完成移动；源行与目标行分别计算排序，再逐帧插值，不能让后续卡片提前补位并穿过移动中的文字。时间线检查卡片完整边界和相邻间距，不能只检查节点中心；放不下就调整卡宽、换行或分阶段呈现。稳定态和移动中分别检查，记录源码、编译组件与实际build版本；几何采样通过仍须复核真实字体与成片帧。

几何复核还要包含固定表头、栏名、注释和标签，不能只统计活动卡片。中心请求卡与左右对照表共存时，明确留出表头阅读区域；用实际字体的成片帧检查字形遮挡。

迭代记录写“发现 → 修改 → 复验证据 → 剩余不确定性”。用户要求多轮时按声音、动作、交付等不同问题开展，不为凑轮数制造修改；不以检查范围有限的成功宣称绝对完美。把稳定有效的教训写回技能，具体本期文案留在项目。
