# 制作与验收细则

## 图文动态演示（默认制作方式）

用户希望像图文丰富的演示稿一样看清图片，同时看到真实的过程变化。图片要有主体、细节和说明价值，不能只是藏在大文字面板背后的装饰。

- 每场先指定三件事：口播在说什么、哪张图片说明它、哪个对象发生什么变化。例如“想说又收回”使用拿手机的人物图，演示输入一段话、删除、发送短回复；“临时答应帮忙”使用同事递文件的图片，演示新增任务挤占休息时间。
- 默认给主图约三分之一画幅，人物表情与关键物件保持可见；演示区与主图相邻，可以局部标注、放大物件或切换景别。按场景需要变化排版，避免整片固定三张文字卡。
- 每场分镜显式选择构图族。标准模板支持 `hook`、`editorial`、`cinematic`、`split-perception`；已有工程若扩展出 `editorial-timeline`、`choice-gallery` 等布局，先确认分镜校验器和实际渲染模板都实现了它们。8 场以上至少使用三种不同构图，相邻场景不能重复；不同构图必须帮助理解。
- 不要只数 `layout` 标签：成片抽帧要比较整屏的标题对齐、主图占比、演示区位置和字幕皮肤；标签不同但画面骨架相同，仍算版式单调。
- 逐场核对“角色—情境—素材”一致：同一个故事角色不能在相邻镜头无解释地换脸、换性别呈现或跳到不相干环境；素材无法匹配时改用手部、背影、物件或抽象演示，不为了用照片硬塞错图。
- 做字幕与画面文字去重检查：把当前字幕组和同屏标题、聊天气泡、任务卡、注释按去标点后的文字比较；同一信息已经被字幕说出时，画面只保留状态、时间、关系或后果等互补信息。语义重复也要人工看，不只依赖字面相同检测。去重时应隐藏整个重复元素（包括底板和边框），不能只删文字后留下空卡片；若保留该元素，必须替换成清晰、有用且不重复的状态信息。
- 开场首帧就要看见与选题相关的内容，不能因淡入导致 0 秒空屏；第一秒呈现动作或问题，前三秒内开始一次能看见的变化。避免标题与首帧长时间不动，先安排输入、选择、揭示或冲突，再补品牌信息。
- **单纯文字飞入、淡入、背景推近不能算内容演示。** 主要讲解段应包含可观察的状态变化：增减、移动、替换、删除、填充、选择、比较或重排；变化必须对应口播，而非加任意光效。
- 补图时先列清单，围绕同一人物、色彩与生活环境生成连贯场景。现代工作、聊天、学习用对应生活图片；山峰、星空只在需要隐喻时使用。经用户授权的同项目图片可以复用，改变关键情境时补新图。
- 保留用户确认的选题和口播；视觉修改不自动授权重写主题。优化内容时减少泛泛赞美，每个主要观点提供具体情境、解释和可执行做法。

### 可复用实现

使用现有 canvas 工程时，读 [动态演示模板与字段说明](illustrated-workflow.md)，使用 `assets/illustrated-motion.html` 与 `scripts/render_illustrated.py`。这是可寻址的 canvas 渲染模板，不是原生 HyperFrames 项目，不能宣称通过了 HyperFrames 检查。新建 HyperFrames 工程仍按 `hyperframes` 工作流组织，可迁移本模板的场景设计思想。

脚本验证每场触发词、素材文件、时间范围，并支持预览、四分之一秒文本边界扫描和 MP4 导出。脚本通过不代表画面好看或声音自然，仍须观看代表性动态片段。

## 开始前

- 先读取现有工程、口播稿、词级时间轴和已选素材；用户提供的参考视频只用于理解节奏、信息密度和视觉语言，不逐帧复制其受保护表达。
- 用户给出多条参考片时，先分别记录每条可借鉴的作用（如版式层级、生活影像、对照演示或镜头节奏），选定一个主视觉语法，再少量吸收其他参考的长处；不要把所有特征堆在同一画面，也不要复制参考片的文案、卡面或镜头顺序。
- 若需要编辑或渲染已有视频，先读 `hyperframes`；画面构图、排版或节奏调整还读 `hyperframes-creative` 与 `hyperframes-animation`。生成或编辑位图时读并使用 `imagegen`。
- 有明确口播时，以口播为内容真相。示意情境可以创作，但标清是示例，不能添加虚假的统计、心理学结论或星座断言；图表与电量等隐喻不伪装成测量数据。

## 内容与镜头原则

1. 开头 3 秒必须给出清晰钩子：反差、痛点或承诺；封面 / 开场只停留足够读懂的时间，迅速进入信息。
2. 每个场景先写出「这句口播要让观众明白什么」，再决定画面。优先用过程、选择、对比、行动路径、情境和结果承接，不用无意义火柴人、抽象连线或为了填空的图标。
3. 画面元素必须跟着相应口播关键词出现。若有词级时间轴：
   - 每个用于触发的关键词都要能在该场文字中找到；不允许缺词后默认回退到场景开头。
   - 不要把后半句结论在前半句字幕出现时提前摆满。
   - 标题与当前字幕要分工：标题概括、提问或补充解释，不逐字复读正在说的句子。特别检查开场 `hook` 的独立标题状态，以及片尾品牌状态；它们可能由模板硬编码，并不受普通 `title_after` 数据检查覆盖。
   - 若标题包含后半句结论，用 `title_after` 在相应口播 cue 开始后再切换。
   - 检查字幕、标题、图表标签与演示动作是否在说同一段内容；标题状态变化也必须使用当前场景实际存在的口播 cue，不得靠估计句序硬排。
4. 视觉应是“编辑感叙事”，而不是 PPT：让一张有含义的大图、景别推进、行动卡、路径 / 物件细节、关键词动效共同讲述。避免全片只有两张背景反复铺用；相邻场景除有意连续镜头外，应切换到语义相关的素材或构图。
5. 星座内容以共鸣式观察表达（如“常见倾向”“可能会”），不把它包装成诊断或事实定论。

## 视觉系统

- 默认暗蓝、暖金、米白星刊调性；生活插画可加入暖光与自然肤色。用户新选的风格优先，每个场景有明确的视觉任务和至少一个主焦点。
- 字体分工：章节大标题可用有质感的宋体 / 衬线；步骤、解释、字幕使用清晰的无衬线；数字和编号可用衬线数字。不要整片只用一种字体或把所有文字做成标题字。
- 正文、步骤和字幕必须在手机上易读。优先减少文字而不是缩小字号；标题通常 64px 以上，正文通常 30px 以上（1080×1920 画布）。
- 格星图本账号字幕按用户确认的样式去除标点，避免字幕上的引号、逗号和句号干扰短句节奏；只清理显示文字，不改旁白文本。若用户对某条任务明确要求保留标点，以当次要求为准。
- 预留安全区：顶部至少 140px，左右至少 80px；字幕区是独立区域，其他关键信息不得压入其上方或与之冲突。导出前以实际帧而非代码坐标确认。
- 图层顺序要明确：背景 → 氛围装饰 → 图片 / 面板 → 连接线 / 轨迹 → 文字 → 字幕。任何线、轨迹、光点都不能穿过文字；需要交叉时，将文本置于更高层或避开文字区域。
- 动效要服务内容，优先让具体物件和关系发生变化。情绪停顿、收尾允许少动；不要为满足数量而强行装饰。
- 以实际活动渲染路径和导出帧验收动画；源码里有绘图函数不代表成片会调用它。抽检对象初态、移动中和终态，移动卡片缩到不可读时只显示简明图标；跨场延续的对象与并列新情境要按叙事顺序复核，不能把新事件画成已完成状态倒退。同时检查填色/状态色、深浅背景上的标题与字幕反差。估算字幕按句组显示时用静态高对比字样，不制造逐字同步假象。

## 配音与同步

- 文案要能自然说出口：短句、具体事例、清楚的指代，避免连续抽象词和每句同一种排比。用户说“讲话奇怪”时同时检查稿子、音色、语速、拼接停顿和字幕。
- 口播先写可直接说出来的话，读出声或试听生成音频后再定稿；长句拆成有呼吸的短句，交替使用短句与解释句。改稿后重建完整音轨和时间轴，不能沿用旧字幕时间。
- 配音正常语速起步；更换音色先制作短试听，已授权可直接制作。保留语音来源、速度和实际检查范围，不能在未听过时宣称自然度已验证。
- 使用波形停顿加字数分配得到的时间只能标作 `waveform-estimated`，不能称作真正词级识别或精确对齐。即使时间轴逐字列出字符，也要检查时间是否真的逐字变化；若一整句字符共享同一组起止时间，就只能称句级同步。缺触发词报错，不回退到零。
- 全片配音生成后，优先用支持中文的 ASR 词级时间戳核对定稿旁白，再把真实词边界映射到字幕句组；先统一简繁与标点再比对文本，检查漏句、重复和明显不匹配，并保存逐句起止时间与阅读速度审计。ASR 对齐差或出现长时间空档时，先人工复核、重识别或修正，不以单次识别结果冒充精确同步。字幕句组可把短于 0.65 秒或快于每秒 9 个汉字作为人工复查提示，不作为机械删改标准。
- 响度数值不能证明音乐好听或人声清晰。条件允许时试听最终 MP4 的开头、代表性讲解段和结尾；否则只报告可验证的响度/编码指标，不声称主观听感已验收。
- 输出前测量全片综合响度与真峰值；格星图口播成片可按约 -14 LUFS、真峰不高于 -1.5 dBTP 作为交付参考，同时保留人声动态与可懂度。报告实际测量值，不能把限值写成测量结果。
- 配音未变则复用其音轨；配音或文字一旦变动，重建时间轴。背景音乐应清晰可感知，同时保持人声可懂度；源轨不同不能照搬固定增益。

## 素材与隔离

- 用户明确提供的图片只能用于该用户授权的项目；不得拿其他项目、其他对话或本机历史项目的图片来填充当前视频。
- AI 生成素材要围绕当前选题单独生成，保存 / 复制到当前项目资产目录后再引用。只从当前任务的生成目录挑选，不按“最新文件”跨项目搜集。
- 素材必须和场景语义匹配；例如“拆目标”可用路线图、笔记、里程碑或工作台，不能误用城市河景或无关照片。
- 新资产和新成片一律使用版本化名称，保留已有交付物，不覆盖、不删除用户内容。
