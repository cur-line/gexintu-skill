# 图文动态演示模板

此标准模板服务于现有的 1080×1920 canvas 工程。标准布局为 `hook`、`editorial`、`cinematic` 和 `split-perception`；特定工程可以扩展，但必须同时核对该工程的校验脚本与实际复制使用的 HTML 模板，不能只在分镜里填写新布局名称。各演示模式会随口播改变图形状态。不是 AI 人物视频，也不会让静态插画中的人物自动说话或活动。

## 输入与运行

工程包含 `storyboard.json`、`build/timeline.json`、本地音轨与本期图片。Python 环境需安装 `playwright` 及其 Chromium；系统提供 `ffmpeg`。在已有环境运行，无需每次重建环境。图片通过 `imagegen` 生成后逐个确认文件身份，复制入工程。模板只内嵌清单里明确引用的文件。

```sh
python /path/to/gexintu/scripts/render_illustrated.py --project /path/to/episode --audit --preview 3,15,32,57,82,103
python /path/to/gexintu/scripts/render_illustrated.py --project /path/to/episode --render /path/to/episode/outputs/video-v2.mp4
```

时间点应按实际内容选择。`--render` 拒绝覆盖已有输出；渲染不删除帧目录。内部页面保存于 `build/illustrated.html`，预览位于 `build/previews`，文字边界报告在 `build/layout-audit.json`。自动边界检查不判断图层遮挡或语义。检查通过后仍看关键帧和动态短片，再导出全片。

`storyboard.json` 顶层：`brand`、`series`、`timing_source`、`voice`（相对工程路径）、`assets`（素材 ID 到相对路径的字典）、`scenes`。

`build/timeline.json` 顶层含 `total` 和 `scenes`。每场含 `id,start,end,duration,narration,words`；words 是 `{t,s,e}` 数组，t 为一个汉字或字符，s/e 是全片绝对秒数。标点不在 words 内。`voice` 是已经混好所需音乐和动作音效的音轨；本脚本不会另外添加BGM或SFX。旧工程的估计时间可使用，但需如实标记来源。

每场画面字段：

- `id`：与时间轴一一对应。
- `show_captions`：可选布尔值；封面场设为 `false`，只影响此场字幕，不关闭全片字幕。
- `layout`：标准值为 `hook`、`editorial`、`cinematic` 或 `split-perception`。8 场以上的完整分镜如设置顶层 `require_layout_variety: true`，渲染器会要求至少三种构图且相邻场景不重复；旧分镜可以省略并默认为 `editorial`。工程自定义值要先在校验器和模板两处实现并抽帧验证。
- `title`：两个短标题字符串的数组。
- `title_after`：可选的渐进式标题数组，例如 `[{"cue":"明天下午","title":["把时间说清楚","明天下午可以吗"]}]`。cue 必须是本场口播中的连续原文；标题只在 cue 对应的时间点后替换，按口播顺序排列。用于避免开场标题提前展示尚未说出的结论。时间轴若为 `waveform-estimated`，标题触发也只能称估算同步。
- `image`：主图 ID；`secondary`：双图对比的第二张图 ID。
- `image_after`：可选 `{cue,asset}`，口播说到 cue 后转入下一幅图。
- `image_stages`：可选的多段 `{cue,asset}` 数组，用于按多个口播节点连续切换主图；每个 cue 必须在本场口播中，先后顺序要与叙事一致。与 `image_after` 同时存在时以 `image_stages` 为准；标准双图对照布局保持两张主图，不应用换图段。
- `mode`：以下表格的演示类型。
- `cues`：按表格顺序给出的口播原文片段，必须存在于本场 words 中。模板使用首次匹配，同一词重复时应给更长的唯一短语。
- `labels`：按表格顺序给出的屏幕文字；尽量控制在 12 字内。
- `gallery`：三选一画廊的三个图片 ID。

字幕与画面标题要分工，避免重复逐字呈现。检查 hook 和结尾状态是否由模板单独硬编码；普通 `title_after` 校验可能覆盖不到它们。逐字展开的字符时间也不一定是词级对齐：若同一句所有字符共享同一对起止时间，应如实标作句级同步。

## 可复用的演示

| mode | 变化 | cues 顺序 | labels 顺序 |
|---|---|---|---|
| battery | 电量逐格减少，与表面回复形成对照 | 疲惫、隐藏 | 表面回复、内心状态 |
| erase-send | 输入长消息→删除→发送短回复 | 被问、开始输入、删除、发送 | 问句、草稿、短回复 |
| queue | 感受被向后推，空间缩小 | 处理工作、感受、延后 | 事项、感受、延后说明 |
| schedule | 新任务长入时间条，休息条缩短 | 已有任务、答应、后悔 | 原任务、新任务、休息 |
| split-perception | 双图与两条示意负担条对比 | 自己、对方理解 | 左视角、右视角、左结论、右结论 |
| reschedule | 任务从今天日历移到明天下午 | 能帮、做不完、另约时间、一起调整 | 今天、另约时间、任务、休息 |
| chat-stop | 一问一答后停住，未说出口的话另置虚线框 | 问、答、期待、停止 | 问句、回答、期待 |
| listen-timer | 10分钟时间环建立，倾听波形运动 | 感受、十分钟、不求解决、陪伴 | 感受、请求、边界 |
| calendar | 六天勾选，第七天空缺或打叉，拒绝全盘否定 | 每天、没完成、否定 | 完成、今天、提示句 |
| timer-switch | 数字与环从30分钟收缩到5分钟 | 半小时、很累、五分钟、持续 | 好状态、疲惫状态、结论 |
| choice-gallery | 三张图片逐项被选中，强调只选一个 | 选项一、二、三、只选一个 | 三项简短名称 |
| reply | 收到关心后发送真实回复 | 关心、实话、账号收口 | 问句、真实回答、收口 |

其中分钟数、天数及部分界面文字是具体演示示例，换新文案时必须检查并按新口播调整模板，不能硬套。新类型按既有 `switch` 扩展，并同步脚本模式清单。示意波形不是从音频测量得到的，电量和负担条不表示心理测量。

## 节奏与构图轮换

- 开场从画面动作开始，不让单张标题页独占前三秒。消息、动作或问题在首秒出现，前三秒内开始状态变化。
- 先按叙事功能分配构图，再填充文案。常见顺序可以是 `hook → cinematic → editorial → split-perception`；整片不应只是把同一栅格换标题。
- 8 场以上建议启用 `require_layout_variety: true`。同一构图的相邻场景应有清楚的连续镜头理由，否则换到下一种布局。
- 口播稿采用可直接说出的短句与长句交替。更改口播后重新合成音轨和时间轴；标点和停顿可能改变每场时长。

## 出片验收

看图时至少能指出主图在解释什么、演示的哪个对象发生了变化；如果只看到字幕或三行卡片，则需要重新设计。避免同样的图反复作为整片背景，允许有叙事理由地重复人物场景。图片区不压暗到丢失细节，也不覆盖人物面部。对最终 MP4 做全片缩略图检查，并单独检查 0 / 0.3 / 1 / 3 秒，验证首帧非空和前三秒变化；不同 `layout` 标签如果整屏标题、主图、演示区和字幕位置几乎不变，仍视为重复版式。

配音试听报告区分实际听感检查与仅元数据/响度检查；响度达标不能代替主观试听。复查准确的交付 MP4（不是只看源图或中间预览），用 ffprobe 检查规格、解码代表性动态片段，并保留音频来源、字幕对齐方法和素材来源记录。

渲染器默认对输入混音做一次约-14 LUFS、-1.5 dBTP响度处理，可用 `--lufs` 与 `--true-peak` 调整。导出后仍须实测并试听；单遍处理不保证最终编码达到指定真峰。
